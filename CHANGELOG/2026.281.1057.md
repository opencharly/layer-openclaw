# 2026.281.1057 — fix(openclaw): carry the repo's new name - layer-openclaw

## Summary

The repo was renamed **`opencharly/openclaw` → `opencharly/layer-openclaw`** to follow the naming convention: a product family is a `layer-<family>` repo (the `layer-agentteams` precedent), never a bare name. This carries the rename into the repo's own content, which still named the old repo.

- `charly.yml` — the `repo:` field and the header comment; the header now states the class rule explicitly, so the next reader cannot repeat the bare-name mistake this repo was created with.
- `box/openclaw/charly.yml` and `candy/openclaw/charly.yml` — the "Home repo" rows inside the two skill bodies.

**Not prose-only, and that is the interesting part:** the skill bodies are emitted into the image's **`ai.opencharly.skill` OCI labels**, so the old repo name was visible in the emitted Containerfile. The rename therefore changes an emitted artifact, which is why this small PR carries a bed run rather than the structural check alone.
