# 2026.282.0448 — fix(bed)!: add the openclaw plugin candy via add_candy, so its verb is served over go-plugin

fix(bed)!: add the openclaw plugin candy via add_candy, so its verb is served over go-plugin

## Summary

The bed's four `openclaw:` steps failed with:

```
cause: the project candy "github.com/opencharly/plugin-openclaw/candy/plugin-openclaw" declares verb:openclaw, but it was not loaded
```

**The plugin was never broken, and neither was the bed's composition.** charly's plugin loader
perf-scopes plugins to what the resolved work references, and a declared-but-unreferenced candy is
never loaded. **The loader's own diagnostic states the remedy**, and this change applies it verbatim:

```
cause: the project candy "github.com/opencharly/plugin-openclaw/candy/plugin-openclaw" declares verb:openclaw, but it was not loaded —
       nothing in the resolved work referenced that word (perf-scoping).
fix: reference the word from the plan being run, or add the candy to the bed's
     add_candy: so the check runner passes it as an extra candy ref
```

So `add_candy:` now carries the plugin candy, and **the runner passes it as an extra candy ref, which is
what makes the loader fetch and serve the provider over go-plugin.**

**A note on the road not taken.** `opencharly/charly#869` tried compiling the plugin into the core
binary instead. That made the verb *register* — which is why the failure's cause changed — but an
in-process plugin **serves no go-plugin broker**, so the steps then failed with
`no go-plugin broker (plugin not served over go-plugin)`. It **traded one failure for another** and was
withdrawn. The comment above the new list records that, so nobody repeats it.
