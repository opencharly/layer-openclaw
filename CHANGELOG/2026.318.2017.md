# 2026.318.2017 — feat(openclaw): bump the gateway npm pin to openclaw@2026.11.3

## Summary

Bumps the gateway layer's npm pin from `openclaw@2026.9.8` to **`2026.11.3`** (npm's
`latest` dist-tag), keeping the four surfaces this repo's `AGENTS.md` ties together in
step, and aligns the bed's `plugin-openclaw` ref with the box's ref so this family's R10
bed runs advisory-free. Tracks `opencharly/layer-openclaw#11`.

| File | Change |
|---|---|
| `candy/openclaw/package.json` | the npm pin itself |
| `candy/openclaw/charly.yml` | the version assertion, the engine-range check prose, the layer skill's dispatcher trigger |
| `.agents/skills/openclaw/SKILL.md` | the pin in the family skill's prose |
| `.agents/skills/openclaw-layer/SKILL.md` | the pin in the layer skill's prose |
| `charly.yml` | the bed's `add_candy:` `plugin-openclaw` ref, aligned to the box's tag |

**Why 2026.11.3 and not `extended-stable`.** npm also serves `extended-stable` =
2026.9.37 (the 2026.9 line, fixes only). That line raises the node floor to
`>=24.22.1 <25 || >=26.12.1`, and it is not what `latest` names. 2026.11.3's declared
engine range is **unchanged** from 2026.9.8 (`>=24.16.0 <25 || >=26.1.0`), so the candy's
engine-floor assertion stays valid as written.

**Why the bed ref rides along.** The bed pinned
`plugin-openclaw:v2026.281.1647` while `box/openclaw` composes `v2026.293.0358`. Two tags
of one candy in one `box=openclaw` scope made the resolver emit *"resolved to multiple git
tags with differing content"* as an advisory on **every** run — including the first run of
this change's gate. R1 says fix such a warning in the change, so the bed's ref now names
the tag the box already ships. The box is untouched, and the proof that the shipped image
did not move is `image-build` taking 36.3s on a full cache hit in the run pasted below —
the image content is the same tree it was before this ref change.
