# 2026.294.1822 — fix(skills)!: the two skill bodies move to the repo root, the one canonical base

## Summary

The two skill bodies move from `candy/openclaw/.agents/skills/<name>/SKILL.md` to
`.agents/skills/<name>/SKILL.md` — the one canonical base at this repo's root — and the candy-dir tree
is deleted in the same commit. This is leg A2 of the ordered wave in opencharly/opencharly#557, and it
copies the shape opencharly/distro-arch#68 landed (leg A9): a pure `git mv`, proven by blob-SHA object
identity, with no dual source and no symlink bridge.

The base both readers resolve is unified in opencharly/sdk — `deploykit.candyRepoRoot`, leg A1, merged
`bdbfd8c` and tagged `v0.2026294.1520`.

**Why this PR waited, and why it no longer does.** The branch has been pushed and move-proven since the
previous round; the PR was withheld because the corpus leg disagreed with the label on this repo's node:
`charly marketplace generate` emitted an `openclaw-layer` body matching neither the branch nor its
newest tag (opencharly/plugin-marketplace#39). opencharly/plugin-marketplace#40 — merged `d0b05ba`,
tagged `v2026.294.1612` — made the project's own pin the authority, and the same three-way comparison
now holds byte-identically on this node (measured under How tested below). #39 is closed, and this PR is
evidence it asked for.

**Why the move is the fix, not a tidy-up.** Two readers, two bases, one layout:

| reader | resolves |
|---|---|
| `plugin-marketplace` (`skillfile.go`) | `<entity SourceRoot>/<tree>/<name>/SKILL.md` — the ref root, i.e. this repo's root |
| `deploykit.CollectSkills` (the label and `charly box validate`) | `<owner candy SourceDir>/<tree>/<name>/SKILL.md` before A1; `<repo root>` after it |

At this repo's newest tag before this branch (`v2026.293.1422`) the corpus reader could reach **neither**
of the two bodies, because both sat beside the candy instead of at the root.

**The landing window, stated rather than hidden.** A reader still on the pre-leg base now refuses this
tree: `charly box validate` reports the bodies missing, loudly, naming the tree it looked in (pasted
below). That is the wave landing in order, not a silent regression, and the same window #68 disclosed.
