# 2026.325.1430 — fix(pins): advance the cachyos import so the namespace loads and the gateway image builds

## Summary

Advances the `cachyos` import pin to the release that carries today's owned-skill carrier chain,
which is what makes this repo's own bed build at all (opencharly/layer-openclaw#14).

```diff
-    - cachyos: '@github.com/opencharly/distro-cachyos:v2026.318.1213'
+    - cachyos: '@github.com/opencharly/distro-cachyos:v2026.325.1412'
```

Two things were wrong at the old pin, and the second is why the bed was red:

1. **The umbrella could not load.** `v2026.318.1213` resolves an arch generation whose imported beds
   predate distro-arch#74, so the loader refuses `openclaw.cachyos.arch.check-arch-vm` (a
   deploy-level bed member with no `host:`). Since the umbrella imports this repo by local path,
   every umbrella verb that loads the project failed with it — `task verify`, `task init`,
   `task sync`, `task worktree`, and the pre-push pin gate.
2. **The gateway image could not be built.** The same generation emits the retired
   `COPY --from=<carrier> .agents/skills` step, so `check-openclaw-pod` died in `image-build` while
   building `cachyos.arch.arch`.

Both are fixed at `v2026.325.1412` (opencharly/distro-cachyos#221, which advanced that repo's own
`arch` and `podcdi` imports to `distro-arch:v2026.325.1112` / `pod-cdi:v2026.325.1329`).
