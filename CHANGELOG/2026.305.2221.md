# 2026.305.2221 — feat(skill): give the openclaw image and layer skills dispatcher triggers

## Summary

A corpus skill with no `triggers:` is unreachable: the R0 dispatcher emits one row per triggers-bearing skill, so an untriggered skill silently has no routing at all. Record: opencharly/marketplace#511.

Both of the OpenClaw family's skill entities carried only `name` / `family` / `owner`, so `DISPATCHER.md` had no `openclaw` or `openclaw-layer` row. This adds to each the triggers that name what the skill actually answers, plus the `category:` field, which was previously absent and therefore defaulted:

- `box/openclaw/charly.yml` — `openclaw-skill`: the headless gateway image on the CachyOS base, deploying OpenClaw with no desktop or browser, and the `check-openclaw-pod` bed.
- `candy/openclaw/charly.yml` — `openclaw-layer-skill`: the gateway candy, its npm pin and node engine floor, the supervised service on `:18789`, its `data` volume at `~/.openclaw`, and the loopback-bound socat relay.

The rows such a change produces were ORIGINALLY not proven — this round proves them by running the generator in both directions, below. The change was carried as an uncommitted working-tree edit in a session worktree whose branch had already been merged; it is re-derived here on fresh `origin/main`, and the stale rename hunks that sat beside it are deliberately not carried (this repo's `main` already names the check-verb skill `/charly-check:openclaw-cmd`, CHANGELOG 2026.293.1243, so that half is superseded).

Head: `5c0d52fd8660746d69e2748ae2f3f749a67cd515`.
