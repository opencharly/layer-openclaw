# 2026.318.2243 — fix(openclaw): advance the CachyOS base to distro-cachyos v2026.318.1213

## Summary

Advances this repo's CachyOS base import from `distro-cachyos:v2026.281.1001` to
**`v2026.318.1213`**. The old base tag pins a `pod-crabbox` tag that no longer exists, and
because the marketplace corpus pins THIS repo, that dead ref had stopped the org's corpus
from regenerating at all.

The chain, both halves measured:

| base tag | `box/crabbox-e2e/charly.yml:9` |
|---|---|
| `v2026.281.1001` (old) | `@github.com/opencharly/pod-crabbox:v2026.274.0652` — **deleted** |
| `v2026.318.1213` (new) | `@github.com/opencharly/pod-crabbox-coordinator:v2026.293.1003` |

`pod-crabbox` no longer serves `v2026.274.0652` at all; distro-cachyos itself switched that
box to the coordinator in 2026.293.1743, but this repo's import predates the switch. Since
`opencharly/marketplace` pins `layer-openclaw`, every `charly marketplace generate` — and
the daily refresh — resolved through this import and died on that ref, which is
`opencharly/marketplace#613`: the refresh has been red since 2026-11-10, and no source's
published pin could advance.

| file | change |
|---|---|
| `charly.yml` | the `cachyos:` import tag, and the comment that explains why the pin exists |

The `AGENTS.md` floor still holds: the import may not go BACK below `v2026.281.1001` (the
tag that dropped the retired openclaw pins whose `openclaw` candy shadows this repo's local
one). `v2026.318.1213` is newer, so that shadowing error cannot return — and it is not a
ceiling, which is what this change corrects.
